## `rein`

A small language for agent decision flows

**Usage:** `rein <COMMAND>`

###### **Subcommands:**

* `check` — Check a project directory, or one .rein file, and print diagnostics
* `run` — Run a flow as a live process. Writes one step per line, reads one answer per line on stdin
* `eval` — Evaluate one function, for debugging. Agents use `rein run` or `rein step`
* `step` — Step the whole flow from `main`. This is the agent-facing interface: answer one key per call
* `describe` — Print a function's schema as JSON
* `graph` — Print the program graph: functions, questions, branches, outcomes, and hand-offs. With answers, mark the path the flow takes. The graph shows functions, not calls: a function called several times with `await` is marked with the answers of its first call
* `debug` — Debug a program in the browser: set inputs and answers, step through, and watch the path the flow takes
* `watch` — Show the agents that use rein now: their programs, answers and the step each run waits on, in a browser page. The flow graph shows functions, not calls: a function called several times with `await` is marked with the answers of its first call
* `list` — List the programs visible from here, as `ls` lists files: names, or `-l` for details. Operands are name globs
* `show` — Print a program's source: its manifest and every .rein file
* `serve` — Serve the agent interface. Holds live runs in memory
* `agent-context` — Print the block an agent needs to use the visible flows
* `hook` — The agent hook entry point. Reads one event on stdin. Run by the agent, not by hand
* `install` — Install a program package: runs `pnpm add` with these arguments
* `uninstall` — Remove an installed program package: runs `pnpm remove` with these arguments. `-g` picks the user folder
* `update` — Update installed program packages: runs `pnpm update --ignore-scripts` with these arguments. `-g` picks the user folder
* `lsp` — Run the language server on stdio
* `dap` — Run the debug adapter on stdio (Debug Adapter Protocol). The VS Code extension starts it

## `rein run`

Run a flow as a live process. Writes one step per line, reads one answer per line on stdin

**Usage:** `rein run [OPTIONS] [FLOW]`

###### **Arguments:**

* `<FLOW>` — Program to run: a `.rein` file, or a name (see `rein list`)

###### **Options:**

* `--root <ROOT>` — Project root. Default: the nearest directory with main.rein
* `--entry <ENTRY>` — Function to start from, as its path under the root without `.rein`. Default: `main`
* `--json` — Speak JSON Lines: one step object out, one `{"key","value"}` answer in, per line



## `rein eval`

Evaluate one function, for debugging. Agents use `rein run` or `rein step`

**Usage:** `rein eval [OPTIONS] [FUNCTION]`

###### **Arguments:**

* `<FUNCTION>` — Function name, as its path under the root without `.rein`. Default: `main`

  Default value: `main`

###### **Options:**

* `--root <ROOT>` — Project root. Default: the nearest directory with main.rein
* `--set <NAME=VALUE>` — Input value as name=value. Repeat for each input
* `--json` — Print the result as JSON



## `rein step`

Step the whole flow from `main`. This is the agent-facing interface: answer one key per call

**Usage:** `rein step [OPTIONS] [PROGRAM]`

###### **Arguments:**

* `<PROGRAM>` — Program to step: a `.rein` file (its folder is the project root), or a name (see `rein list`)

###### **Options:**

* `--entry <ENTRY>` — Function to start from, as its path under the root without `.rein`. Default: `main`
* `--root <ROOT>` — Project root. Default: the nearest directory with main.rein
* `--flow <FLOW>` — Program to step, by name (see `rein list`). Same as the positional program
* `--answer <KEY=VALUE>` — Answer as key=value, such as `merge_pr.ci=green`. Repeat for each answer
* `--input <NAME=VALUE>` — Value of a `string` parameter of the entry function, as name=value. Repeat for each input
* `--stdin` — Read the whole request as JSON from stdin. Output is always JSON
* `--json` — Print the response as JSON

## `rein graph`

Print the program graph: functions, questions, branches, outcomes, and hand-offs. With answers, mark the path the flow takes. The graph shows functions, not calls: a function called several times with `await` is marked with the answers of its first call

**Usage:** `rein graph [OPTIONS] [PROGRAM]`

###### **Arguments:**

* `<PROGRAM>` — Program to draw: a `.rein` file, or a name (see `rein list`). Default: the project around the current directory

###### **Options:**

* `--root <ROOT>` — Project root. Default: the nearest directory with main.rein
* `--refs` — Draw only the references: one node per function, one edge per reference
* `--entry <ENTRY>` — Walk the flow from this function, as its path under the root without `.rein`. Default: the program's entry
* `--answer <KEY=VALUE>` — Walk the flow with this answer, as key=value, such as `main.task=merge`. Repeat for each answer
* `--input <NAME=VALUE>` — Walk the flow with this value of a `string` parameter of the entry, as name=value. Repeat for each input
* `--format <FORMAT>` — Output format. Default: `html` for a `.html` FILE or with --open, else `mermaid`

  Possible values:
  - `mermaid`
  - `dot`
  - `json`
  - `html`:
    One page that draws the Mermaid diagram in a browser

* `-o`, `--output <FILE>` — Write to FILE instead of stdout. A `.svg` or `.png` FILE is rendered from DOT by Graphviz `dot`
* `--open` — Open the page in the default browser. Without -o, write it to a temporary file first

## `rein list`

List the programs visible from here, as `ls` lists files: names, or `-l` for details. Operands are name globs

**Usage:** `rein list [OPTIONS] [PATTERNS]...`

###### **Arguments:**

* `<PATTERNS>` — Show only the programs that these names match. Shell-style globs such as `pr-*`. Default: every program

###### **Options:**

* `--json` — Print the full records as JSON. Honors the operands, -a, -r and -t. -l and -1 do not apply
* `-l` — Long format: one program per line, with scope, version, name, path and description
* `-1` — One name per line, even on a terminal
* `-a`, `--all` — Also show shadowed programs, marked with the scope that wins the name
* `-r`, `--reverse` — Reverse the order
* `-t` — Sort by the modification time of each program's entry file, newest first. Default: by name

## `rein install`

Install a program package: runs `pnpm add` with these arguments.

The arguments go to pnpm unchanged, so any pnpm flag works. `-g` or `--global` installs for the user: it runs in `<user programs folder>/npm/`, and rein does not pass it on. Without `-g`, it runs in the repo's `rein/npm/`. Outside a repository, use `-g`. `--ignore-scripts` is added first, unless the arguments set it.

**Usage:** `rein install <ARGS>...`

###### **Arguments:**

* `<ARGS>` — Arguments for `pnpm add`, such as `pr-handling@^1`, `file:../pr-handling` or `--save-exact`
